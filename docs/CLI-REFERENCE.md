# CLI reference

`git-cortex` compiles two CLI binaries from [crates/cortex-cli](../crates/cortex-cli/Cargo.toml): `git-cortex` ([main.rs](../crates/cortex-cli/src/main.rs)) and `cortex` ([cortex.rs](../crates/cortex-cli/src/bin/cortex.rs)). Both entrypoints call `cortex_cli::run()` in [crates/cortex-cli/src/lib.rs](../crates/cortex-cli/src/lib.rs).

## Invocation and repository discovery

Running `git cortex <command>` tells Git to invoke `git-cortex` on `PATH` with `"cortex"` as the first argument. Before `clap` parses the command line, `cortex_cli::run()` checks whether `raw_args.len() > 1 && raw_args[1] == "cortex"` and removes that leading token. Invoking `git-cortex <command>`, `git cortex <command>`, or `cortex <command>` produces the same behavior.

Source builds (`cargo build` or `cargo install`) and the npm wrapper ([package.json](../npm/package.json)) provide both `git-cortex` and `cortex`. Prebuilt release archives generated by [release.yml](../.github/workflows/release.yml) compile `--bin git-cortex` only.

`clap` handles `-h` / `--help` and `-V` / `--version` at both the root level and the subcommand level, printing usage or `git-cortex 0.1.0` and exiting with `0`.

Before dispatching any subcommand, `cortex_cli::run()` calls `CortexRepo::discover(None)` in [repo.rs](../crates/cortex-storage/src/repo.rs#L18-L45), which searches upward from the current working directory using `git2::Repository::discover(".")`. Bare repositories fail with an error. For linked `git worktree` checkouts, `CortexRepo::resolve_commondir` reads `<repo.path()>/commondir`, joins it onto `repo.path()`, and canonicalizes the target so all linked worktrees share `<common_git_dir>/cortex/state.db` and `refs/cortex/*` references. `CortexRepo::discover` creates `<common_git_dir>/cortex` if it is missing.

Every subcommand except `init` and `doctor` calls `CortexDb::open(&db_path)` before matching the command. Opening `state.db` creates the SQLite file and runs schema version `1` migrations if the file does not exist yet. `doctor` runs prior to `CortexDb::open` so inspecting an uninitialized repository leaves `state.db` absent, whereas `symbols` runs after `CortexDb::open` even though it reads no database tables.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Command succeeded, `verify-invariants` found zero `BLOCKING` violations, or `hook` completed `post-commit`, `post-checkout`, `post-merge`, or an unknown hook name. |
| `1` | Unhandled runtime, Git, SQLite, I/O, or AST error returned from `main()`; record missing in `tombstone show` or `invariant show`; one or more `BLOCKING` violations in `verify-invariants` or `hook pre-commit`; child process exited with `1` or died from a signal. |
| `2` | `clap` argument parsing error (unknown flag, missing required option, or invalid subcommand). |
| `124` | Child process exceeded `--timeout <seconds>` in `exec`. `hook pre-commit` uses `124` internally when a `verification_test_cmd` exceeds its 30-second limit and then exits `1`. |
| Child code | `exec` and `hook` exit directly through `std::process::exit(exit_code)` with the child process or hook status code. |

## Command summary

| Command | Subcommands | Primary purpose |
| --- | --- | --- |
| `init` | | Initialize `state.db`, fetch refspec, Git hooks, instruction blocks, and `.mcp.json`. |
| `status` | | Print branch, `HEAD`, dirty hash, and epistemic counts. |
| `inspect` | | Query active and stale Tombstones and Invariants for a file or symbol. |
| `symbols` | | Extract and print AST symbol URIs and hashes for a file. |
| `exec` | | Run a command with passive Edit, Fail, Revert candidate tracking. |
| `tombstone` | `add`, `list`, `show`, `revoke` | Record, inspect, or revoke negative-knowledge Tombstones. |
| `invariant` | `add`, `list`, `show`, `reaffirm`, `revoke` | Record, inspect, reaffirm, or revoke Causal Invariant Locks. |
| `checkpoint` | | Snapshot the working tree to `refs/cortex/checkpoints/<chk_id>` and record `checkpoints` metadata. |
| `rewind` | | Restore a checkpoint working tree after backing up dirty state and synthesizing a Tombstone. |
| `handoff` | `export`, `import` | Export or import a 4 KB `EpistemicHandoff` envelope or A2A task wrapper. |
| `verify-invariants` | | Run static AST drift checks across active invariants. |
| `promote` | | Commit unpromoted local Tombstones, Invariants, and Events to `refs/cortex/ledger`. |
| `sync` | | Fetch, union-merge, reindex, and push `refs/cortex/ledger` with a remote. |
| `reindex` | | Rebuild local `records` and `record_symbols` cache from `refs/cortex/ledger`. |
| `hook` | | Execute internal Git lifecycle hook handlers. |
| `mcp-serve` | | Run the JSON-RPC 2.0 MCP server over `stdin` and `stdout`. |
| `doctor` | | Report repository paths, database counts, ledger state, hooks, and agent config files. |

## Commands

### init

```text
git cortex init [--hooks] [--agents-md] [--mcp]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--hooks` | `bool` | `true` | Install chained `pre-commit`, `post-commit`, `post-checkout`, and `post-merge` Git hooks. |
| `--agents-md` | `bool` | `true` | Append the `<!-- git-cortex:begin -->` protocol block to `AGENTS.md` and `CLAUDE.md`. |
| `--mcp` | `bool` | `true` | Create or merge `mcpServers["git-cortex"]` in `.mcp.json`. |

All three fields in [crates/cortex-cli/src/lib.rs](../crates/cortex-cli/src/lib.rs#L38-L45) declare `#[arg(long, default_value_t = true)]` on `bool`, so `clap` exposes `--hooks`, `--agents-md`, and `--mcp` as positive flags only. Passing any of them sets it to `true` (already the default), and no `--no-hooks`, `--no-agents-md`, or `--no-mcp` negation flags exist.

Side effects in [init.rs](../crates/cortex-cli/src/init.rs):

- Opens `<common_git_dir>/cortex/state.db` and runs schema migrations.
- Configures `remote.origin.fetch` to include `+refs/cortex/ledger:refs/remotes/origin/cortex/ledger` (replacing any legacy `+refs/cortex/ledger:refs/cortex/ledger` rule) and adds `+refs/heads/*:refs/remotes/origin/*` if no `refs/heads/` fetch rule is present.
- Resolves `core.hooksPath` (absolute, relative to `workdir`, or `<common_git_dir>/hooks` by default) and appends `# --- git-cortex:begin ---` / `# --- git-cortex:end ---` blocks calling `git-cortex hook <name> || exit $?` (falling back to `cortex hook <name> || exit $?`). Sets `0o755` permissions on Unix.
- Appends the normative agent instructions block to `AGENTS.md` and `CLAUDE.md` when `<!-- git-cortex:begin -->` is missing.
- Creates `.mcp.json` or merges `{"git-cortex":{"command":"git","args":["cortex","mcp-serve"]}}` into existing `mcpServers`.

Exits `0` on success or `1` on Git, SQLite, or filesystem errors.

### status

```text
git cortex status [--json]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--json` | `bool` | `false` | Print machine-readable status JSON. |

Example `--json` output:

```json
{
  "branch": "main",
  "head_commit": "b143df91234567890abcdef1234567890abcdef12",
  "working_tree_hash": "wt:clean",
  "tombstones_count": 2,
  "invariants_count": 1,
  "call_graph_edges": 3,
  "active_hypotheses": 1
}
```

`tombstones_count` and `invariants_count` count all `TOMBSTONE` and `INVARIANT` rows in `records` across all branches and lifecycle states (including revoked and stale entries). `call_graph_edges` and `active_hypotheses` count rows matching the current branch.

Side effects: opens `state.db` (creating it if absent) and reads the current branch, `HEAD` SHA, and working tree dirty hash (`wt:clean` or `wt:sha256:<16hex>`). Makes no Git ref or worktree changes. Exits `0` on success or `1` on Git or SQLite failure.

### inspect

```text
git cortex inspect <filepath> [symbol_name] [--json]
```

| Argument / Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `<filepath>` | `String` | Required | Target file path, normalized via `normalize_rel_path`. |
| `[symbol_name]` | `Option<String>` | `None` | Optional substring/suffix filter applied to matched records. |
| `--json` | `bool` | `false` | Emit serialized `InspectResult` JSON. |

When `symbol_name` is set, Tombstones match if any `target_symbols[].symbol_uri` ends with or contains `symbol_name`, and Invariants match if `guarded_symbol.symbol_uri` or any `upstream_dependencies[].symbol_uri` contains `symbol_name`.

Default output prints `formatted_markdown`: HTML-fenced Tombstones (`<!-- CORTEX_TOMBSTONE_BEGIN ... -->`) and Invariants (`<!-- CORTEX_INVARIANT_BEGIN ... -->`) for active records, `<!-- STALE ... -->` or `<!-- REVOKED ... -->` comments for drifted or revoked records, or `<!-- CORTEX_INSPECT: No active Tombstones or Invariants found for <filepath> -->`.

Example `--json` output ([inspect.rs](../crates/cortex-engine/src/inspect.rs#L11-L20)):

```json
{
  "filepath": "src/lib.rs",
  "symbol_name": "helper",
  "current_symbols": [
    {
      "uri": "src/lib.rs#helper",
      "scope_chain": "helper",
      "kind": "FUNCTION",
      "ast_hash": "ast:sha256:9f2c1b0a4d8e7711",
      "byte_range": { "start": 0, "end": 34 },
      "line_range": { "start": 1, "end": 2 }
    }
  ],
  "active_tombstones": [],
  "stale_tombstones": [],
  "active_invariants": [],
  "stale_invariants": [],
  "formatted_markdown": "<!-- CORTEX_INSPECT: No active Tombstones or Invariants found for src/lib.rs -->"
}
```

`inspect` evaluates `EventType::Revoke` events (ignoring `EventType::Supersede`) and compares stored `ast_hash` values against live disk files. Deleted or missing symbols appear in `stale_tombstones` and `stale_invariants` (`[record, reason]` pairs); `DerivedStatus::Orphaned` is never emitted.

Side effects: `inspect` opens `state.db` and reads target files plus any referenced upstream dependency files on disk. It runs no shell commands and leaves Git refs and worktree files unchanged. Exits `0` on success or `1` on I/O, AST, or SQLite errors.

### symbols

```text
git cortex symbols <filepath> [--json]
```

| Argument / Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `<filepath>` | `String` | Required | File path to parse, normalized via `normalize_rel_path`. |
| `--json` | `bool` | `false` | Emit `Vec<Symbol>` JSON. |

Tree-sitter extraction supports `.rs` (`::` scope separator), `.ts`/`.mts`/`.cts`, `.tsx`, `.js`/`.mjs`/`.cjs`/`.jsx`, `.py`/`.pyi`, and `.go` (`.` scope separator). Unsupported text files and supported files with zero extracted symbols emit a single `<file>` entry (`SymbolKind::File`) hashed from trimmed non-empty lines. Files over 2 MiB or containing a NUL byte in the first 1,024 bytes emit `<binary>` (`SymbolKind::File`, `line_range: { "start": 1, "end": 2 }`, first 16 hex chars of full-file SHA-256).

Example `--json` output:

```json
[
  {
    "uri": "src/lib.rs#helper",
    "scope_chain": "helper",
    "kind": "FUNCTION",
    "ast_hash": "ast:sha256:9f2c1b0a4d8e7711",
    "byte_range": { "start": 0, "end": 34 },
    "line_range": { "start": 1, "end": 2 }
  }
]
```

Side effects and implementation note: `symbols` does not query or mutate SQLite tables, yet `cortex_cli::run()` opens `<common_git_dir>/cortex/state.db` before running `Commands::Symbols`. The command therefore requires a Git repository with a writable `.git/cortex` directory and creates `state.db` if absent. Exits `0` on success or `1` on file read, parse, or DB open failure.

### exec

```text
git cortex exec [-t|--timeout <seconds>] <command>...
```

| Argument / Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `-t`, `--timeout <u64>` | `u64` | `0` | Timeout in seconds (`0` disables timeout enforcement). |
| `<command>...` | `Vec<String>` | Required | Executable followed by trailing arguments (`trailing_var_arg = true`). |

`exec` spawns `command[0]` directly with `std::process::Command::new` inside `repo.workdir` without a shell wrapper. Pass `sh -c "..."` or `cmd /C "..."` explicitly when shell syntax is needed.

Behavior and side effects ([exec.rs](../crates/cortex-capture/src/exec.rs)):

- Snapshots AST hashes of dirty tracked files against `HEAD` before starting the child process (untracked files are ignored).
- Reads child `stdout` and `stderr` concurrently on two threads with unbounded `read_to_end`, forwards them to terminal `stdout` and `stderr`, and persists the trailing 4,096 UTF-8-safe bytes as `output_tail`.
- Enforces `--timeout` when greater than `0` by polling every 25 ms, killing the Unix process group (`SIGKILL` to `-(pid)`) or Windows process tree (`taskkill /F /T /PID <pid>`), and assigning exit code `124`.
- Inserts a row into SQLite `execs`. `exec.rs` currently mints `execs.id` with `IdPrefix::Checkpoint` (`chk_<26-ULID>`).
- On non-zero exit when tracked symbols changed relative to `HEAD`, checks `execs` for an earlier clean-tree (`tree_hash = "wt:clean"`) run with matching `(cmd, signature)`. If none matches, inserts a `FAILED` row into `candidates` (`cand_<26-ULID>`).
- Runs `reconcile_candidates`: any `FAILED` candidate whose touched symbols reverted to `base_ast_hash` promotes the reverted subset to a `CaptureMode::AutoRevertDetected` Tombstone (`author_harness: "git-cortex/passive-capture"`).

Exits with the child exit code, `124` on timeout, or `1` if the child died by signal or spawning failed.

### tombstone

#### tombstone add

```text
git cortex tombstone add [-s|--symbols <URI,...>] -m|--approach <text> -r|--reason <text> [-c|--cmd <text>] [--sig <text>]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `-s`, `--symbols` | `Vec<String>` | `[]` | Comma-delimited symbol URIs (`src/auth.rs#verify`) or file paths (normalized to `<path>#<file>`). |
| `-m`, `--approach` | `String` | Required | Summary of the failed approach (scrubbed for secrets). |
| `-r`, `--reason` | `String` | Required | Explanation of why the approach failed (scrubbed). |
| `-c`, `--cmd` | `String` | `""` | Command that reproduced the failure (scrubbed). |
| `--sig` | `String` | `""` | Normalized error signature (scrubbed). |

Note on `-s`/`--symbols`: `clap` does not mark `symbols` as `required = true`, so omitting `-s` stores a Tombstone with an empty `target_symbols` array. When a target file exists on disk and specifies a named scope missing from extracted symbols, `record_tombstone` fails with `SymbolNotFound` (exit `1`). `<file>` scopes with zero extracted symbols and missing files fall back to `ast:sha256:0000000000000000`.

Side effects: writes a `TOMBSTONE` row (`tmb_<26-ULID>`, `origin = "LOCAL"`, `promoted = 0`, `author_harness = "cortex-cli"`, `capture_mode = "MANUAL"`, `verification_evidence.exit_code = 1`) into `records` and `record_symbols` in `state.db`. Leaves `refs/cortex/ledger` untouched. Exits `0` or `1`.

### checkpoint

```text
git cortex checkpoint [-m|--message <text>]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `-m`, `--message` | `String` | `"Manual checkpoint"` | Checkpoint objective string stored in commit and SQLite metadata. |

Side effects ([checkpoint.rs](../crates/cortex-engine/src/checkpoint.rs), [snapshot.rs](../crates/cortex-storage/src/snapshot.rs)):

- Creates a snapshot commit at `refs/cortex/checkpoints/<chk_id>` (parented on `HEAD` when present) using a temporary index `<repo.path()>/cortex/tmp_index_<chk_id>` seeded from `HEAD` and updated with all working-tree deletions, edits, and untracked files. Live `.git/index` and working tree files stay unchanged. In linked worktrees, `snapshot.rs` places the temporary index under `repo.path().join("cortex")` (the worktree gitdir) while `state.db` resides in `commondir/cortex`.
- Inserts a row in SQLite `checkpoints` with `state_json = {"edge_count":0,"hypothesis_count":0}`. The CLI command always writes empty edge and hypothesis counts; populating `call_graph_edges` and `hypotheses` uses MCP `cortex_checkpoint_state` or CLI `handoff import`.

Exits `0` on success or `1` on Git or SQLite failure.

### rewind

```text
git cortex rewind <checkpoint_id> [-r|--reason <text>]
```

| Argument / Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `<checkpoint_id>` | `String` | Required | Checkpoint ID matching `refs/cortex/checkpoints/<checkpoint_id>`. |
| `-r`, `--reason` | `Option<String>` | `None` | Failure reason for the synthesized Tombstone (defaults to `"Aborted exploration rolled back via cortex rewind"`). |

Side effects ([rewind.rs](../crates/cortex-engine/src/rewind.rs)):

1. Verifies `refs/cortex/checkpoints/<checkpoint_id>` exists.
2. Snapshots the current dirty working tree to `refs/cortex/backups/<new_chk_id>`.
3. Compares modified and untracked files on disk against the checkpoint tree to collect changed or added symbols (deleted files and deleted symbols are skipped).
4. Snapshots untracked files under `refs/cortex/untracked/<checkpoint_id>`.
5. Checks out `refs/cortex/checkpoints/<checkpoint_id>` with `force().remove_untracked(true)` and resets `.git/index` to match the checkpoint tree.
6. Inserts a `CaptureMode::RewindSynthesized` Tombstone (`author_harness = "git-cortex/rewind"`, `command = "cortex rewind"`, `error_signature = "ABORTED_WORKTREE_REWIND"`) into `records` and `record_symbols`.

`rewind` does not restore SQLite `call_graph_edges` or `hypotheses` to their checkpoint state. Exits `0` on success or `1` if the checkpoint reference is missing or Git/SQLite fails.

### handoff

#### handoff export

```text
git cortex handoff export [--a2a] [--out <path>]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--a2a` | `bool` | `false` | Wrap `EpistemicHandoff` in a Google A2A JSON-RPC 2.0 `tasks/send` envelope. |
| `--out` | `Option<PathBuf>` | `None` | Write JSON to `<path>` (prints to `stdout` when omitted). |

`handoff export` builds an `EpistemicHandoff` for the current branch (`objective = "Active development task"`), omits Tombstones revoked via `REVOKE` events, sorts remaining Tombstones by salience (`0.50 * proximity + 0.35 * bm25 + 0.15 * 1.0`), populates `do_not_re_read_unchanged` where `sha256_digest(bytes) == file_reads.blob_oid`, and sheds fields across 7 priority tiers so the raw `EpistemicHandoff` stays at or below `4096` bytes (see [SCHEMAS.md](SCHEMAS.md#epistemichandoff-and-a2a-task-envelope)). With `--a2a`, that `EpistemicHandoff` is embedded under `params.metadata["https://git-cortex.dev/a2a-extension/v0.1"]` with `id = "task_handoff"` and instruction `"Continue development"`.

Side effects: `handoff export` reads Git state and `state.db`, and optionally writes `--out`. It writes nothing to `records` or `refs/cortex/ledger`. Exits `0` or `1`.

#### handoff import

```text
git cortex handoff import [--file <path>]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--file` | `Option<PathBuf>` | `None` | Read raw `EpistemicHandoff` JSON from `<path>` (reads `stdin` when omitted). |

`handoff import` expects a raw `EpistemicHandoff` JSON object and rejects `--a2a` JSON-RPC wrappers. Side effects: upserts `verified_call_graph` into SQLite `call_graph_edges` and `active_hypotheses` into `hypotheses` for the current branch (rejecting non-finite or out-of-range `[0.0, 1.0]` confidence values). Exits `0` or `1`.

### verify-invariants

```text
git cortex verify-invariants [--staged] [--working-tree] [--branch]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--staged` | `bool` | `false` | Verify index stage-0 blobs (falling back to working tree if unindexed, then `HEAD` tree if empty). |
| `--working-tree` | `bool` | `false` | Explicit spelling of the default scope; ignored in `lib.rs`. |
| `--branch` | `bool` | `false` | Verify symbols in the `HEAD` commit tree (falls back to working tree if `HEAD` has no commit). |

Precedence when multiple scope flags appear: `--staged` takes priority over `--branch`, and `WorkingTree` is the default when neither is set.

`verify-invariants` runs static AST hash checks only ([lib.rs:571](../crates/cortex-cli/src/lib.rs#L571) calls `verify_invariants`, never `verify_and_reaffirm_invariants`) and never executes `verification_test_cmd`. It skips `REVOKE`-targeted contracts, checks both `guarded_symbol` and `upstream_dependencies`, prints `BLOCKING` entries in `report.violations` to `stderr`, and ignores `WARNING` entries in `report.warnings` for pass/fail and stdout output.

Side effects: opens `state.db` and reads target files into the in-memory `SymbolCache`. Makes no SQLite or Git writes. Exits `0` when `report.passed` is true (zero `BLOCKING` violations) or `1` when any `BLOCKING` violation exists.

### promote

```text
git cortex promote
```

Takes no flags or positional arguments. Reads all `TOMBSTONE`, `INVARIANT`, and `EVENT` rows from SQLite `records` where `promoted == 0`, writes them as blobs under `v1/{tombstones|invariants|events}/<trailing-2-lowercase-chars>/<id>.json` onto `refs/cortex/ledger` (5-attempt compare-and-swap retry loop using Git `user.name` / `user.email`, defaulting to `"git-cortex"` / `"cortex@git-cortex.dev"`), and updates each row in `state.db` to `promoted = 1` and `origin = "LEDGER"`. Exits `0` or `1`.

### sync

```text
git cortex sync [remote] [--rebase]
```

| Argument / Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `[remote]` | `Option<String>` | `"origin"` | Git remote name (`sync_ledger_internal` defaults `None` to `"origin"`). |
| `--rebase` | `bool` | `false` | Force retry/re-merge handling on push errors even if stderr lacks standard rejection substrings. |

Side effects ([sync.rs](../crates/cortex-engine/src/sync.rs)):

1. Runs `git fetch <remote> refs/cortex/ledger:refs/remotes/<remote>/cortex/ledger` (logs a notice if missing remotely).
2. Calls `CortexLedger::merge_commits` to fast-forward or set-union merge `refs/remotes/<remote>/cortex/ledger` into `refs/cortex/ledger`. Aborts with `"Tamper alert: conflicting content detected for record path ..."` if both trees hold the same path with different blob OIDs.
3. Calls `CortexLedger::reindex_into_db` to upsert ledger records into `state.db`.
4. Runs `git push <remote> refs/cortex/ledger:refs/cortex/ledger` up to 5 attempts with `50 * (1 << attempt)` ms backoff, re-fetching and merging on divergent rejection errors.

Exits `0` on success or `1` if merging or pushing fails or retries exhaust.

### reindex

```text
git cortex reindex
```

Takes no flags or positional arguments. Walks the tree at `refs/cortex/ledger` (returning `0` indexed records if the ref does not exist), classifies blobs by path (`/tombstones/` -> `TOMBSTONE`, `/invariants/` -> `INVARIANT`, otherwise `EVENT`), extracts `branch_context` (default `"main"`) and `created_at` (fallback `Utc::now()`), rebuilds `record_symbols`, and upserts rows into SQLite `records` (`origin = "LEDGER"`, `promoted = 1`) in 500-item `Immediate` transactions.

Implementation note: `walk_tree_and_index` splits `symbol_uri` with `.split('#').next()` while AST parsing uses `rsplit_once('#')`, so paths containing `#` truncate at the first `#` during ledger reindex. Exits `0` or `1`.

### hook

```text
git cortex hook <name>
```

| Argument | Type | Default | Description |
| --- | --- | --- | --- |
| `<name>` | `String` | Required | Hook identifier: `pre-commit`, `post-commit`, `post-checkout`, or `post-merge`. |

Behavior ([hook.rs](../crates/cortex-cli/src/hook.rs)):

- `pre-commit`: calls `verify_and_reaffirm_invariants(repo, db, DiffScope::Staged, true)`. Unlike `verify-invariants`, when a `BLOCKING` contract drifts and has a non-empty `verification_test_cmd`, `hook pre-commit` executes that command in `repo.workdir` via `sh -c` (Unix) or `cmd /C` (Windows) with a 30-second timeout (`124` internally on timeout). Commands exiting `0` trigger automatic `reaffirm_invariant` (`author = "git-cortex/pre-commit"`), mutating the `INVARIANT` row (`promoted = 0`), appending a `REAFFIRM` event, and clearing that violation. Exits `1` if any `BLOCKING` violation remains; exits `0` otherwise.
- `post-commit`: calls `promote_local_records`, ignores errors, and exits `0`.
- `post-checkout`: calls `reconcile_candidates`, ignores errors, and exits `0`.
- `post-merge`: calls `CortexLedger::reindex_into_db` and `reconcile_candidates`, ignores errors, and exits `0`.
- Any other `<name>` prints `[git-cortex] Unknown hook: <name>` to `stderr` and exits `0`.

### mcp-serve

```text
git cortex mcp-serve
```

Takes no flags or positional arguments. Runs `McpServer::run_stdio` synchronously over `stdin` and `stdout`, accepting both `Content-Length`-framed LSP headers and raw NDJSON lines (`protocolVersion: "2024-11-05"`). Exposes `cortex_inspect_symbol`, `cortex_record_tombstone`, `cortex_checkpoint_state`, `cortex_handoff_pack`, `cortex_verify_invariants`, and `cortex_record_invariant`, and executes `reconcile_candidates` on every `tools/call` request. See [MCP-AND-INTEGRATION.md](MCP-AND-INTEGRATION.md) for tool schemas and [spec/ECP-v0.1.md](spec/ECP-v0.1.md) for the protocol specification.

### doctor

```text
git cortex doctor
```

Takes no flags or positional arguments. Runs prior to `CortexDb::open`, so it never creates `state.db` on an uninitialized repository. Prints diagnostics for repository root, common `.git` directory, branch and 8-character `HEAD` prefix, `state.db` presence and `TOMBSTONE`/`INVARIANT` counts (opening read/write only if `state.db` already exists), `refs/cortex/ledger` OID, installed hooks in `core.hooksPath` or `<common_git_dir>/hooks`, `AGENTS.md` / `CLAUDE.md` markers, and `.mcp.json`.

Exits `0` whenever repository discovery succeeds, even if optional configuration checks report warnings (`!`) or missing files (`-`), and `1` if repository discovery fails.
